through a `useAppStore((s) => s.x)` selector.

## `useAppStore.getState()` classification

Context = where the call executes: **effect** (inside `useEffect`/`useLayoutEffect`),
**callback** (inside `useCallback`), **handler** (event handler / nested function in a
component), **render** (component body / `useMemo`), **render-init**
(`useState`/`useRef` initializer), **function** (plain module function: services,
helpers). Access = **action** (calls an action), **read** (reads one field),
**snapshot** (keeps the whole state object, usually to read several fields).

### Assessment

- **effect / callback / handler / function (338)** — the intended use:
  reading the latest state inside async work or event handlers without
  subscribing (no re-render, no stale closure). No change needed.
- **render / render-init (4)** — non-reactive reads during render.
  All are deliberate snapshots:
  - `src/components/mq/AudioDebugPanel.tsx:172` — render, read `listeningEvents`
  - `src/components/mq/MainView.tsx:234` — render, snapshot
  - `src/components/mq/PublicPlaylistsView.tsx:54` — render-init, read `publicPlaylistDeepLink`
  - `src/components/mq/yandex/YandexImportFlow.tsx:174` — render, read `playlists`
  The `MainView` home-feed signature reads likes/dislikes/favourite artists
  non-reactively inside `useMemo`; it refreshes when `tasteProfile` changes.
  Low risk, but if a like does not refresh the feed, this is the place.
- **snapshot (104)** — mostly `const st = useAppStore.getState()` followed by several reads;
  fine in handlers/effects.
